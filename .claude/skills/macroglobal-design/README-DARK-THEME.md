# 🌗 Тёмная тема MGCRM — как устроена и как реализовать

Тёмная тема — часть дизайн-системы (`tokens/dark.css`), навигационная navy-палитра,
портированная из брифа MACROSALES 2.0. Система **light-first**: светлые токены — база,
тёмная тема — opt-in слой, который переопределяет семантические токены на корневом scope.

---

## 1. Как включается

Добавь на корневой элемент приложения (или любой подддерево) **любой** из селекторов —
`dark.css` матчит все три:

```html
<div class="mg-app" data-theme="dark"> … </div>   <!-- канонично -->
<div class="mg-dark"> … </div>                      <!-- альтернатива -->
<div class="surface dark"> … </div>                 <!-- так сделано в макетах redesign -->
```

Внутри поддерева **ничего** не меняется — переключается только корень. Все компоненты и
экраны читают токены, а `dark.css` подменяет их значения разом.

В коде репо (Vue/PrimeVue) переключение идёт штатно — через пресет темы PrimeVue + те же
SCSS-токены. Значения 1:1 совпадают с `dark.css`.

---

## 2. Что переопределяет `dark.css` (не хардкодить это по месту!)

Тёмная тема меняет **только значения токенов**, тремя слоями:

1. **Семантические роли** (`semantic.css`): поверхности, текст, границы, статусы, действия,
   инпуты, бренд-хром сайдбара.
2. **Page-мост `--c-*`** — которым пользуются страницы redesign (tasks/funnel/contacts/
   settings): `--c-page · --c-board · --c-card · --c-border · --c-border2 · --c-text ·
   --c-text2 · --c-muted · --c-hover`.
3. **Примитивные тинт-ремапы** — чтобы пастельные чипы (`--mg-green-100` фон + `--mg-*-700/900`
   ink) читались на navy: в тёмном scope они флипаются в тёмные тинты того же тона + светлый ink.

**Правило:** компонент всегда пишет токен (`background: var(--c-card)`,
`color: var(--mg-status-success-text)`), и в обеих темах выглядит правильно **без единого
`if dark`**. Никаких отдельных «тёмных» правил в компонентах.

---

## 3. Ключевые значения (для сверки с кодом репо)

**Поверхности:** фон `#0A1426` → карточка `#111E38` → muted `#172847` → hover `#1F3157`.
**Текст:** основной `#EAF0FA`, вторичный `#B4C2DA`, muted `#8593B0`.
**Границы:** `#27395C` (default), `#3A4F78` (strong), фокус `#4C7DF0`.
**Бренд-акцент светлеет:** `--mg-primary-900` = `#4C7DF0` (в светлой — navy `#172747`),
hover `#6E99FF`. Это ключевой инвариант: navy-акцент на navy-фоне исчез бы, поэтому в тёмной
он становится светло-синим.
**Статусы (мягкий тинт того же тона, без чёрно-белых флипов):** success text `#8FD3A0`,
danger text `#F4A293`, warning text `#E6B98C`, info text `#94C2EC` — каждый на подложке
`rgba(...,.16–.18)`.
**Сайдбар** темнеет, но **остаётся navy** (`#091020`), не уходит в нейтральный серый.
**Тени глубже:** `--mg-shadow-card: 0 4px 14px rgba(3,8,20,.55)`.

## 4. Чек-лист приёмки тёмной темы (для QA)

- [ ] Переключение light↔dark меняет ВСЁ поддерево, без «залипших» светлых пятен.
- [ ] Нет чистого чёрного (`#000`) и чистого белого фона — только navy-шкала.
- [ ] Бренд-акцент в тёмной — светло-синий (`#4C7DF0`), а не тёмный navy (иначе кнопки/ссылки «пропадают»).
- [ ] Статус-пилюли читаемы: светлый ink на тёмном тинте того же тона.
- [ ] Контраст текста ≥ AA: основной `#EAF0FA` на `#0A1426`/`#111E38`.
- [ ] Сайдбар navy, не серый; активный пункт — светлая полоса `#6E99FF`.
- [ ] Инпуты: фон `#111E38`, бордер `#3A4F78`, фокус `#6E99FF`.
- [ ] Нигде не хардкожены «тёмные» цвета — всё через токены (`npm run lint:ds` зелёный).

---

## 5. Живой пример

Открой любой макет из `design-handoff/redesign/` в браузере и нажми переключатель темы
(иконка солнца/луны в шапке) — увидишь эталонное поведение обеих тем. `settings.html`
показывает переключатель и раздел «Внешний вид» с выбором темы.
