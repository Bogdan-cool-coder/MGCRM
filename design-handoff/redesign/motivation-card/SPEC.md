# ТЗ: Мотивационные карты (МК) — два экрана

**Версия:** 1.0 · **Дата:** 2026-07-02  
**Автор:** designer  
**Статус:** Draft — ожидает ревью

---

## Контекст и цели

Мотивационная карта (МК) — помесячный salary-slip менеджера по продажам. Показывает: план отдела, личные показатели, компоненты зарплаты (оклад / комиссия / KPI / бонус / командный бонус), итог ЗП и прогноз. Два отдела: **Global** и **Global AI**. Поступления мультивалютные (₽ / AED / KZT / UZS → конвертация в base-валюту).

**Проблема черновых прототипов:**
- 7-колоночная таблица на узкой ширине — ячейки нечитаемы, горизонтальный скролл неприятен.
- Слабая иерархия: итог ЗП и прогноз бонуса не выделены — ключевые числа теряются.
- Нет ритма: всё одним блоком, нет визуальной группировки секций.
- Черновые контролы в конструкторе: поля без лейблов, непонятная структура шагов.
- Цвет % одинаков везде — нет семантики успех/варн/данж.
- Числа в «колонке факт» без разбивки по валютам.

**Два экрана:**
1. `/manager-cabinet/motivation` — МК менеджера (read-only).
2. `/settings/motivation-builder` — Конструктор МК (admin/director).

### Цветовая семантика % выполнения

| Порог | Цвет | Токен bg / text |
|---|---|---|
| ≥ 100% | success | `--mg-status-success-bg` / `--mg-status-success-text` |
| 80–99% | warning | `--mg-status-warning-bg` / `--mg-status-warning-text` |
| < 80% | danger | `--mg-status-danger-bg` / `--mg-status-danger-text` |
| Нет данных / план не задан | muted | `--c-muted` |

Применяется к: колонке «%» в таблице ЗП, чипу выполнения плана отдела, индикаторам FTM/NEW INCOME.

### Форматирование чисел

- Деньги: `1 200 000 ₽` / `800 000 AED` / `40 036 989 UZS` — пробел-разделитель тысяч, символ после числа с пробелом.
- Крупные суммы в hero-блоке: `≈ 40,0 млн UZS` (decimal-запятая).
- % без дроби, если целое (`100%`), с одним знаком если дробное (`98,5%`).
- Курс: `1 RUB = 151 UZS` (формат label).

### Компонент `PctTag` (переиспользуемый)

Тег процента с семантикой. Вшит в таблицу ЗП и индикаторы.

```
[  164%  ]  → success (зелёный)
[   92%  ]  → warning (оранжевый)
[   54%  ]  → danger (красный)
[   —    ]  → muted (нет данных)
```

Props: `value: number | null`, `size: 'sm' | 'md'` (sm=11px для таблицы, md=14px для чипов).  
Реализация: `Tag` PrimeVue с динамическим `severity` через computed. Не новый компонент — надстройка над Tag.

## ЭКРАН 1 — МК менеджера (`/manager-cabinet/motivation`)

### Назначение

Менеджер видит свою текущую мотивационную карту: план отдела, компоненты ЗП, итог, прогноз командного бонуса, индикаторы KPI, мультивалютный факт. Только чтение.

**Роли:** `manager` — видит только свою карту. `director` — может переключаться между подчинёнными (см. параметр `?user_id=`). `admin` — любой пользователь.

**Маршрут:** `/manager-cabinet/motivation?year=2026&month=4`  
**Где в коде:** `front/src/pages/ManagerCabinetPage/MotivationTab.vue` (новый таб внутри существующего `ManagerCabinetPage`)

### Секция 2: План отдела

**Компонент:** `MkDeptPlan.vue`  
**Фон:** `--c-card`, border, radius lg, padding `16px 20px`.

Шапка секции: `ПЛАН ОТДЕЛА ПО НОВЫМ ПОСТУПЛЕНИЯМ` (13px / uppercase / ls 0.06em / 600 / --c-muted), рядом `Отдел Global · Апрель 2026` (12px / --c-muted).

Тело: горизонтальная раскладка в 1 строку (flex, align-center, gap 24px):

```
[Число план] → ProgressBar → [Число факт] [PctTag]
800 000 ₽        ████████░░      1 586 365 ₽  [198%]
12px muted        (полная ширина) 14px/700     success
```

**ProgressBar:** PrimeVue `ProgressBar`, `value = Math.min(pct, 100)`, высота 8px, radius 4px.  
- Цвет трека: `--mg-gray-200`.  
- Цвет заполнения: берётся от `pctSeverity` (success=`--mg-green-500`, warning=`--mg-orange-500`, danger=`--mg-red-500`).  
- Переполнение (>100%): ProgressBar всегда показывает 100% заполнения + отдельный `PctTag` рядом с реальным числом.

Мультивалютный факт: под числом факта — мелким (11px / --c-muted), в скобках, если валюты расходятся: `(1 200 000 ₽ + 300 000 AED → 1 586 365 ₽ base)`. Раскрывается по клику на иконку `pi-info-circle 12px`.

**Edge-case «план не задан»:**
```
[pi-exclamation-circle 16px --mg-orange-500]  «План отдела на этот месяц не задан»
                                               Кнопка «Задать план» (только для director/admin)
```

#### Колонка A: Таблица компонентов `MkSalaryTable.vue`

Карточка: `--c-card`, border, radius lg, padding 0 (шапка + тело).

**Почему НЕ широкая 7-колоночная таблица:**  
На 1024px-экране 7 равных колонок = ~130px каждая — нечитаемо. Решение: стековая карточная раскладка с 2-уровневой иерархией.

**Структура строки** (каждая позиция — отдельный строковый блок):

```
┌──────────────────────────────────────────────────────────┐
│  [иконка 20px]  ОКЛАД              [Tag severity]        │
│                 Базовая ставка · выплата в след. месяце  │
│                                                          │
│  ┌─── Показатели ───┐   ┌─── ЗП ─────────────────────┐  │
│  │ План    17 000 000 UZS│   │ ЗП план  17 000 000 UZS │  │
│  │ Факт    17 000 000 UZS│   │ ЗП факт  17 000 000 UZS │  │
│  │ %       [100%]        │   │                         │  │
│  └────────────────────────┘   └──────────────────────────┘  │
└──────────────────────────────────────────────────────────┘
```

Каждая строка:
- Шапка строки (48px): иконка-плитка 28×28 (radius sm, `--mg-primary-100`, иконка `--mg-primary-900`) + **Название позиции** (14px/600) + `Tag` (описатель позиции) + Toggle-шеврон (`pi-chevron-down`).
- При раскрытии (default: развёрнуто): сетка 2×2 (`d-flex gap-3 flex-wrap`):
  - «Показатели» (2 ячейки: План / Факт) — слева.
  - «ЗП» (2 ячейки: ЗП план / ЗП факт) — справа.
  - «%» — отдельная строка через весь блок с `PctTag`.
- Под-заметка (12px / --c-muted): «Выплачивается СРАЗУ» — курсивом, если есть `payment_note`.
- Разделитель 1px `--c-border` между строками.

**Позиции и иконки:**

| Позиция | Иконка | Примечание |
|---|---|---|
| Оклад | `pi-wallet` | фикс |
| Комиссия | `pi-percentage` | % от поступлений |
| KPI | `pi-chart-bar` | FTM-встречи |
| Бонус | `pi-star` | разовый |
| Командный бонус | `pi-users` | пул / дележ |

### Помесячная навигация


## ЭКРАН 2 — Конструктор МК (`/settings/motivation-builder`)

### Назначение

Руководитель или admin настраивает МК для менеджера: выбирает сотрудника, включает/выключает позиции ЗП, вводит плановые значения, настраивает командный бонус и мультивалюту. Живой пересчёт итога.

**Роли:** только `director`, `admin`. Менеджер — редирект на `/manager-cabinet/motivation`.

**Маршрут:** `/settings/motivation-builder?user_id=&year=&month=`  
**Где в коде:** новый раздел в `SettingsPage` → `SectionMotivationBuilder.vue`  
**Зависимость:** подключается в `useSettings.ts` как section `'motivation-builder'` с role-gate `['admin', 'director']`.

### Валидация (Конструктор)

Инлайн-валидация — `blur`-гарды (не VeeValidate, ручная).

| Поле | Правило | Ошибка |
|---|---|---|
| Сотрудник | обязателен | «Выберите сотрудника» |
| Оклад (план) | > 0, если позиция включена | «Введите сумму оклада» |
| Валюта оклада | обязательна | «Выберите валюту» |
| % комиссии | 0 < x ≤ 100 | «Укажите % от 0 до 100» |
| Пул бонуса | > 0, если командный бонус включён | «Введите размер пула» |
| Порог % | 0 < x ≤ 100 | «Порог должен быть от 1 до 100» |
| Часть 1 % | 0 < x < 100 | «Укажите от 1 до 99» |
| Курс валюты | > 0, если ручной режим | «Введите курс > 0» |

Ошибка: 12px / `--mg-status-danger-text` под полем, border поля меняется на `--mg-status-danger-border`.  
При сабмите с ошибками — первое невалидное поле получает focus, `Toast severity="error"` «Исправьте ошибки в форме».

### Права (Конструктор)

Role-gate в компоненте:
```vue
const canEdit = computed(() => authStore.user?.role === 'admin' || authStore.user?.role === 'director')
```

`v-if="canEdit"` на всей форме. Если нет доступа — редирект `router.push('/manager-cabinet/motivation')` в `onMounted`.

## Backend-зависимости (открытые вопросы)

**B-1.** `GET /api/motivation/cards/me?year=&month=` — endpoint личной карточки менеджера. Возвращает: snapshot плана, факты всех позиций, total_local, курсы, ftm_count, new_income_breakdown, dept_plan, dept_fact, dept_pct. Нужен у `sales-specialist` / `finance-specialist`.

**B-2.** `GET /api/motivation/plans/:userId/:year/:month` — чтение плана (для конструктора). Отдельный объект SalaryPlan + CommissionRule + TeamTarget.

**B-3.** `POST /api/motivation/plans` — создание/обновление плана. Body: позиции, план/валюта, командный бонус, курсы.

**B-4.** `GET /api/exchange-rates/latest` — актуальные курсы с источником. Уже существует `ExchangeRatesPage` с `ManualRateDialog` — возможно, расширить существующий endpoint.

**B-5.** `GET /api/users?role=manager&q=&managed_by=me` — список менеджеров для AutoComplete. Параметр `managed_by=me` для role=director.

До готовности B-1…B-5 frontend-specialist реализует с моками (`/src/mocks/motivation*.json`).

## Ответы юзера 2026-07-02 (обновления ТЗ — приоритет над разделами выше)

- **ОВ-1 (курсы) — ЗАКРЫТ:** курсы тянутся **АВТОМАТИЧЕСКИ** (API уже подключён, `ExchangeRatesPage`/exchangerate). Ручной ввод курсов в конструкторе **убрать**; шаг 5 = base-валюта + авто-подтянутые курсы (read-only) + «обновлено {дата}, источник» + кнопка «Обновить». Никаких editable-инпутов курса.
- **ОВ-4 (статус) — ЗАКРЫТ:** МК из `черновик → финализирована → выплачено` переводит **бухгалтер (accountant) ИЛИ директор/РОП (director)**. Добавить в конструктор контрол статуса (кнопки «Финализировать» / «Отметить выплаченным») с role-gate `['accountant','director','admin']`. У менеджера в кабинете — статус только read-only (Tag).
- **ОВ-5 (KPI) — ЗАКРЫТ:** KPI **гибкий, НЕ только FTM**. В конструкторе позиция KPI конфигурируется: **имя KPI** (текст) + **тип** [Количество (шт.) · Сумма (валюта) · Вручную (отметка выполнено/не выполнено)] + план + ЗП за выполнение. Допускается **несколько KPI**. В кабинете KPI-карточка(и) рендерится по конфигу (имя + план/факт по типу; для «вручную» — бейдж Выполнено/Не выполнено вместо %). Хардкод «FTM» убрать (FTM — лишь один из возможных KPI). Индикатор NEW INCOME (доход) остаётся отдельно.

## Фиксы «криво» (чеклист для фронта)

Это прямые требования к реализации, фиксирующие проблемы черновых прототипов:

1. **Иерархия:** «ЗП ФАКТ» (28px/700/navy) и «Прогноз бонуса итого» (20px/700) должны быть крупнейшими числами на экране. Всё остальное — мельче.
2. **Таблица-не-таблица:** позиции ЗП на узком экране (<1024px) — карточки в 1 колонку, не горизонтальная 7-колоночная таблица со скроллом. На ≥1024px — DataTable с фиксированными шириной колонок.
3. **Ритм:** между секциями gap `$space-4` (16px в `g-4`). Внутри карточки — разделитель 1px `--c-border`. Eyebrow-заголовки секций (13px uppercase) единообразны.
4. **% всегда семантический:** ни одного `%` без `PctTag` (success/warning/danger/muted). Никакого «чёрного процента».
5. **Деньги:** всегда `1 200 000 ₽` (пробел-разделитель, символ после). В hero — дополнительно аббревиатура `≈ 40,0 млн UZS`.
6. **Тёмная тема:** hero-число `--mg-primary-300` (не white), фон итог-карточки `--c-card` (не прозрачный). Проверить через `qa-tester`.
7. **Плотность таблицы конструктора:** `DataTable size="small"`, `showGridlines`. Лейблы строк не более 180px, InputNumber заполняет ячейку.
8. **Скроллбар скрыт:** `scrollbar-width: none` глобально на strange-scrollable-областях (карточка поступлений).
9. **Выравнивание:** числа в таблице — right-align. Лейблы — left-align. В hero-карточке — left-align (не centered).
10. **Loading:** Skeleton точно по форме элементов (не один большой прямоугольник на всю страницу).
